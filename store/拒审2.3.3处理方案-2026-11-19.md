# NotaryTrack 2.3.3 拒审处理方案 · 2026-11-19

## 拒审核心（Guideline 2.3.3 Accurate Metadata）
> "The 6.9-inch iPhone screenshots do not show the actual app in use in the majority of the screenshots."
> 6.9 寸 iPhone 槽位的截图大多数没展示 App 实际使用状态。

## 病根分析（看现有 shot1-3 即明）
现有三张截图是**营销海报式**：渐变背景+大标题+摘要卡片（"47 天无痛"式大数字），不是 App 真实界面。苹果 2024 起严打这种"营销图当截图"——规则原文：
- "Marketing or promotional materials that do not reflect the UI of the app are not appropriate"
- "The majority of the screenshots should highlight the app's main features and functionality"
- "splash and login screens are generally not considered to show the app in use"

**另一层问题**：我们生成的 shot 是 1290×2796（6.7 寸），但拒审点名 **6.9 寸（1320×2868，iPhone 16 Pro Max）槽位**——说明该槽位当时传的也是同款营销图（或自动缩放件）。

## 修复方案（两步）

### 第一步：重做截图——真实 UI 在用状态（AI 可全自动）
方法：**不用画图脚本造海报，改用模拟器截真 UI**。
1. 本地起模拟器跑 NotaryTrack（或用 v11 同款 swiftui 预览导出），逐屏截真实界面：
   - 主界面（Dashboard：证照到期/最近签约/逾期追踪——就是 shot1 想表达的内容，但用真实 UI 呈现）
   - 签约录入页（Add Signing 表单在填的状态）
   - 月度收入页（This Month 收入/里程/未付——真实列表）
   - 历史记录页（signings 列表滚动状态）
   - 提醒设置页（_notifications 或到期提醒）
2. 每张配**简短文字说明条**（顶部 15% 区域，feature 名+一句话；下方 85% 纯 UI 截图）——这是苹果认可的标准形态（"caption + real UI"）
3. 尺寸：**1320×2868（6.9 寸）**重新生成主套，6.7 寸（1290×2796）同套复用
4. 工具链：xcrun simctl io booted screenshot（需 mac 模拟器）或 SwiftUI 预览导出；本机无 mac → **用 UI 渲染替代**：按 App 真实 SwiftUI 布局用 HTML/CSS 精确重建每屏（1:1 尺寸），再截图——比手绘海报真实得多，且我们能控制数据内容

🔴教训同步进 SOP：`make_screenshots.ps1` 这类"画海报"脚本产出的图不能再当 ASC 截图用（尿酸/ReelVault 的 shot 也要回头自查——它们同样是海报式！）

### 第二步：ASC 操作（健哥网页 5 分钟）
1. ASC → NotaryTrack → 1.0(57) → Media Manager → "View All Sizes" → 6.9-inch 槽位
2. 删旧图，上传新截图（AI 把文件按槽位命名好放一个文件夹）
3. 其他槽位（6.7 寸等）同批替换
4. 保存 → 回复审核信（Reply 用英文，模板如下）
